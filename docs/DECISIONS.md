# Decision log

Why things are the way they are. Newest last. If you want to reverse one of these, raise it with the agency owner first.

1. **The agent edits structured content, not code.** It submits operations on a JSON site document built from a fixed section library. This is what makes "never breaks the site", "always on brand" and "never touches checkout" enforceable in code. Trade-off: limited range, no new components. (Partly reversed by decision 14: it can now write checked HTML and CSS inside the document.)

2. **Brand tokens are locked.** Colours and the two typefaces live in `public/styles.css`. The agent controls layout, order, theme and words, and (since decision 14) its own HTML and CSS, but only with those colours and fonts.

3. **The demo site copies the OTMENS theme closely.** Jacob should recognise his own brand, then watch the agent change it. A more creative redesign of the base site (arched hero, marquee, staggered steps) was built and then **reverted at the owner's request**: "go back to the original design, the agent is the main build anyway." Those layouts later returned as optional variants the agent can choose.

4. **Two separate sites.** The public website and the OT Studio are separate services. The Studio keeps its own copy of the site and never reads the real otmens.com. (Owner's requirement.)

5. **Approve and push are separate.** Approve creates a stored, numbered version; push makes a version live. Every version is kept and can be viewed, pushed or restored. (Owner's requirement.)

6. **Hosting is GitHub plus Railway**, from the same repo: the website runs `npm start`, the Studio runs `node studio.js`. Pushing to `main` deploys both.

7. **File-based storage in `DATA_DIR`.** Chosen for speed of building a two-day proof of concept. It requires a persistent volume and a single Studio instance.

8. **Campaigns draft immediately.** The first live test asked five questions and drafted nothing. The agent now drafts in the same turn, builds on the existing offer when no terms are given, proposes dates for Jacob to confirm, and asks at most three things.

9. **The agent never invents a discount or price**, and blocks its own draft with a `[NEEDS FROM JACOB: ...]` marker when it needs a fact such as a renewal price.

10. **Agent runs happen in the background with polling.** A single long-held HTTP request was cut off after about 30 seconds in production while the agent was still working.

11. **The agent must be bold when asked.** The owner judged copy-only edits too timid. The library gained hero variants, a statement band, a marquee, staggered steps, expanding photo panels, tilted plan cards, photo features, an image closing panel and four background themes; `agent/SKILL.md` gained "How bold to be" (a large request requires a concept, a different opening, three structural moves and a cut). Based on research into Anthropic's frontend-design skill and the community skills built on it (Impeccable, Taste Skill), adapted to work inside locked brand tokens, because those skills all assume free code and new fonts and colours.

12. **Model: `claude-opus-5-5` at effort `medium`**, with server-side refusal fallbacks and a retry without them if rejected. Both are configurable by environment variable.

13. **Generation spend is kept low.** The owner asked not to use many Higgsfield credits or tokens. Five images were generated in total.

14. **The agent writes HTML and CSS, inside checks (15 November 2026).** Reverses part of decision 1 at the owner's request: with content-only edits, "Run a Black Friday sale" changed too little to impress in the demo. The agent can now write `custom` sections (its own HTML and section-scoped CSS, which can replace the home hero) and a site-wide `global.css`. Both live inside the site document, so they are drafted, previewed, approved, versioned and undone like everything else. Limits, enforced in `src/code.js` and `src/guard.js`: no JavaScript or event handlers, no forms or iframes, no outside URLs, brand palette and fonts only, links must resolve, images from the library only, visible text goes through the same health-claim and voice checks, and agent CSS cannot target the footer, legal or prescription notices. Protected pages render without the agent's CSS. Rejected alternative: letting the agent edit the repository's code files, which would bypass versions, preview and undo, and would need a developer to review every change. Trade-off: "never breaks the site" is now "never breaks the site's function"; a badly composed custom section can still look wrong, which preview and approval are there to catch.

15. **The agent's instructions are split into four skills (15 November 2026).** At the owner's request, to match the ask (design, copywriting, flow building and development) and so each can be improved on its own: `agent/skills/copywriting.md`, `design.md`, `flow-building.md`, `development.md`. `agent/SKILL.md` stays the core (brand, hard limits, size of the ask, campaigns, learning) and wins over any skill. All four skills are sent with every request rather than chosen per request, because a campaign needs all of them and the prompt is cached. Each reply reports which skills it used, shown as tags in the Studio chat.

16. **Campaign images through the Higgsfield API, checked by a model (15 November 2026).** The owner chose for the agent to generate images itself rather than use a pre-made set. The deployed app uses Higgsfield's API (prepaid dollar balance, key in Railway) because the Higgsfield MCP connection only works inside Claude sessions. The agent requests images through a tool, before it answers; the server generates, reviews and stores them, and the agent only ever sees images that passed. The review uses the same Claude model as the agent at low effort, because the review is a safety check and a cheaper model was not requested. Images are stored on the Studio volume and proxied by the website, so they are versioned with the drafts that use them. Capped at 3 per request to control spend. A fifth skill, imagery, holds the art direction. Model: Marketing Studio 2.5 Flare, after SOUL (a portrait and fashion model) produced a mockup-looking product shot the owner rejected; Flare takes product reference photos, so OT products match the real ones. The check scores quality against a real OTMENS photo and fails anything under 7/10, because a rule-only check passed an image the owner called "really bad". The owner wants campaign imagery broadly (mood, season, lifestyle), not only product shots, generated live by the agent for any occasion.

17. **The agent may write JavaScript, forms and iframes, and load outside resources (15 November 2026).** The owner removed the "no JavaScript" rule ("I'm not worried. That's a stupid rule."), wanting the range of a real front-end developer, including smooth scrolling and interactive pieces. Custom sections gain a `js` field; the site gains `global.js`, `global.scripts` (up to 6 library URLs) and outside links and images. Kept, because they protect something other than the agent's range: brand colours and fonts in all CSS; nothing aimed at the footer, legal text or prescription notices (in CSS and JS); scripts must parse; health-claim and voice checks also read the quoted strings in scripts; no collecting personal or health information (instructions); agent code never runs on checkout, portal or intake. Added so the agent's scripts can't approve or push their own drafts: Studio previews are served with a `Content-Security-Policy: sandbox` header (and sandboxed iframes), so they run in an isolated origin, and the Studio API refuses POSTs that aren't JSON from the Studio's own origin. Trade-offs, stated to the owner: text that a script builds at run time can't be fully checked, so the health-claim check on scripts is best-effort and the preview review is the real safeguard; a badly written script can break interaction on a page (the content still renders).

18. **Lenis for smooth scrolling; no GSAP (15 November 2026).** Lenis (MIT licence) is installed as a dependency, served by both apps at `/vendor/lenis.min.js`, and on by default on every page (`global.smoothScroll: false` turns it off). Mouse and trackpad only; touch keeps native scrolling; off for reduced motion; not on protected pages. GSAP was considered and dropped by the owner because of its licence (the "Standard 'no charge' license" after Webflow's acquisition, with terms about competing products that were not reviewed). The guard blocks GSAP in `global.scripts` and in agent code.

19. **Borrowed rules from Emil Kowalski's apple-design skill, not the whole skill (15 November 2026).** The owner asked whether to give the agent the `apple-design` skill (github.com/emilkowalski/skills, MIT; Apple's WWDC talks, mainly *Designing Fluid Interfaces*). Reviewed in full: about 5,700 tokens, mostly gesture physics for app-style interfaces (drag, springs, momentum, haptics) that a marketing site doesn't use; it also tells the model to default to system fonts and use translucent glass toolbars, which conflict with the locked brand fonts and the design skill's no-glass rule, and it opens with a canned chat greeting. Installing it would add about 40% to every agent request for little gain. Instead, about ten rules were adapted into `agent/skills/design.md` ("Craft") and `agent/skills/development.md` ("How it should feel"), with attribution: instant press feedback, never locking out input, spatial consistency, weight without bounce, transform/opacity-only animation, size-specific type, accessibility settings as signals, deciding the feeling, simplicity over minimalism, deliberate values, calm motion, soft edges. About 800 tokens.

20. **Image quality through direction, references and a calibrated check, not a model switch (15 November 2026).** The owner called the agent's campaign images "AI slop". A bake-off of the same prompt on Flare (with OTMENS photos as style references), SOUL Cinema and Recraft V4.1 Pro (with the brand palette) showed Flare with references and a photographic prompt was clearly best; SOUL Cinema baked in a film border, Recraft looked like a filtered stock photo. So: every image is now generated with two real OTMENS photos as style references (automatic, in `src/images.js`); the imagery skill was rewritten around what failed (light source in frame, orange/teal splits, over-sharpened texture lists, kitsch staging, stock tropes, superlatives), drawing on the open-source image-master (hoodini; no licence file, so ideas only, no text copied) and product-photography (sanky369, MIT) skills; and the image check now looks for named "AI tells", each capping the score at 5, and judges the actual saved file. Calibrated on seven images already judged by eye: every slop-type image scored 5 or less, both images written to the new rules scored 6, so the pass mark is 6 (`HF_MIN_IMAGE_SCORE`). Images made before this (pipeline 1) are no longer offered to the agent for reuse. SOUL Cinema and Recraft remain selectable with `HF_IMAGE_MODEL`.

21. **OT Studio is neutral black and white (15 November 2026).** At the owner's request the Studio's own interface no longer uses the OTMENS brown and gold: near-black backgrounds, white text and a white primary button, grey dividers, muted green for live and passed checks, muted blue for focus and the "Changed" outline in previews. Jacob's site keeps its brand. Reason: a tool shouldn't compete visually with the site it edits.

22. **More design freedom, fonts kept (15 November 2026).** The owner judged the agent too constrained ("we're not giving it enough freedom") after reviewing three tools from a social post: Framer Motion (now Motion, MIT), the UI/UX Pro Max skill and 21st.dev. Motion was adopted as the recommended animation library (the agent could already load it; the development skill now says how). UI/UX Pro Max was not adopted: it runs Python searches the agent can't run, and its job is choosing palettes, fonts and styles, which conflicts with keeping Jacob's brand. 21st.dev was not adopted: React and shadcn components for a developer's build, while this site has no React or build step. Relaxed: colour (any shade of the brand's warm family from hue 20° to 60°, any neutral, and one campaign accent hue family per site, checked in code across all agent CSS; hsl() allowed; named colours only when neutral); headline limits (100 characters, two accent words); the design skill's blanket bans on gradients, glass, shadows, bento and badges (now "when they serve the idea", with only true giveaways still banned); motion ("use motion", at least one memorable moment per campaign, instead of "calm only"); campaigns may depart from the everyday look. Kept: the two typefaces (the owner didn't ask to change fonts; they are the most recognisable part of the brand), and every health, legal, protected-area and factual rule.
